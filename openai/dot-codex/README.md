# Codex Environment Map

This directory mixes two kinds of content:

- human-managed configuration and guidance
- generated runtime state, caches, logs, and sessions

When cleaning up or tuning the environment, treat those two groups differently.

## Human-managed areas

These are the files and directories you should edit intentionally:

- `AGENTS.md`: global engineering operating standard for Codex.
- `config.toml`: global Codex runtime configuration, model selection, sandbox/approval defaults, MCP servers, trusted projects, and shell environment policy.
- `agents/`: specialist agent definitions such as `security-auditor`, `reviewer`, and `pr-explorer`.
- `evals/`: local evaluation harness, including cases, baselines, fixtures, scripts, schemas, and eval documentation.
- `templates/`: reusable repository companion-doc templates such as architecture, build/test, security, performance, code-review, and interop guidance.
- `skills/.system/`: system-provided Codex skills shipped with the environment.

## Custom skills

User-authored skills are not stored here.

Custom skills live under:

- `/home/marti/.agents/skills`

Current custom skill groups include:

- build and validation
- orchestrated implementation and review
- security review
- interop review
- PR summary / structured review output
- OpenAI-specific knowledge

In practice:

- `~/.codex/skills/.system` = built-in/system skills
- `~/.agents/skills` = custom/user-managed skills

## Generated or runtime state

These areas are normally generated by Codex or supporting tooling and should not be hand-edited unless you are debugging a specific issue:

- `auth.json`: authentication/session state.
- `history.jsonl`: local interaction history.
- `cache/`: cached data.
- `log/`: log output.
- `logs_*.sqlite`, `state_*.sqlite`: local runtime databases/state stores.
- `sessions/`: saved session artifacts.
- `shell_snapshots/`: captured shell environment snapshots.
- `tmp/`: transient helper/runtime artifacts.
- `.tmp/`: plugin-sync and other temporary internal artifacts.
- `models_cache.json`, `version.json`: runtime metadata/cache state.

The presence of both `tmp/` and `.tmp/` is operationally normal here:

- `tmp/` currently holds transient argument/runtime artifacts.
- `.tmp/` currently holds internal plugin-sync scratch state.

Do not remove either one casually. Inspect contents first if disk use or corruption is suspected.

## Recommended mental model

Use this split when navigating the environment:

- policy: `AGENTS.md`, `config.toml`
- specialization: `agents/`, `skills/`, `/home/marti/.agents/skills`
- evaluation: `evals/`
- reusable docs/templates: `templates/`
- generated state: logs, caches, sessions, sqlite files, `tmp/`, `.tmp/`

## Cleanup guidance

If you want to clean up the Codex environment safely, prefer this order:

1. review and simplify `config.toml`
2. keep `AGENTS.md` concise and high-signal
3. keep `agents/`, `evals/`, and `templates/` structurally stable
4. document custom skills in `/home/marti/.agents/skills`
5. only inspect or prune generated/runtime areas when you have a specific reason

## What not to optimize prematurely

Do not restructure the environment just for aesthetics if the current layout already matches Codex runtime behavior.

The highest-value organization improvements are:

- clear documentation of the environment map
- consistent skill/instruction quality
- stable eval semantics
- low-noise runtime hygiene
