Codex autonomous setup prompt for a freshly cloned agentcore repo
=================================================================

Read this entire file first. Then configure this machine's Codex setup from
this repository without asking follow-up questions unless continuing would risk
destroying existing local configuration with no recoverable backup.

Fast path
---------

If Python 3 is available, use the checked-in bootstrap helper first with the
target machine's working Python executable:

    python3 scripts/bootstrap_codex_environment.py

On Windows, prefer python instead of python3 unless python3 is explicitly known
to be configured:

    python scripts\bootstrap_codex_environment.py

For a no-write preview:

    python3 scripts/bootstrap_codex_environment.py --dry-run

On Windows:

    python scripts\bootstrap_codex_environment.py --dry-run

The script is stdlib-only and implements the install, merge, backup, and
validation rules below. If Python 3 is unavailable or the script fails before it
can safely proceed, follow the manual contract in this file.

Goal
----

Use this repository as a portable baseline for Codex and custom agent skills.
Install or merge the durable, human-managed files into the live user home on
this machine:

- repo openai/dot-codex/ -> live ~/.codex/
- repo openai/dot-agents/ -> live ~/.agents/

This is not a raw home-directory restore. Do not copy secrets, sessions,
caches, logs, sqlite databases, histories, shell snapshots, temporary files,
virtual environments, or machine-local runtime state.

Operating rules
---------------

1. Work autonomously.
2. Prefer safe merge behavior over blind overwrite.
3. Before replacing any existing live file, create a timestamped backup under:
   ~/.codex-agentcore-backups/<YYYYMMDD-HHMMSS>/
4. Preserve target-machine local configuration when it exists.
5. Do not copy ignored or runtime-only files even if they exist in the working
   tree.
6. Do not write secrets to logs or final output.
7. If a required command is missing, continue with the best available standard
   tool and report the limitation.
8. If live ~/.codex or ~/.agents does not exist, create it with mode 700 when
   practical.

Files to read before making changes
-----------------------------------

From the repository root, read:

- README.md
- openai/README.md
- openai/dot-codex/README.md
- openai/dot-agents/README.md
- openai/dot-codex/config.toml

Treat openai/dot-codex/config.toml as the portable baseline. Treat any existing
live ~/.codex/config.toml as the machine-local overlay.

Install and merge plan
----------------------

Create these live directories when needed:

- ~/.codex
- ~/.codex/agents
- ~/.codex/rules
- ~/.agents
- ~/.agents/skills

Copy these files or directories from the repo to the live locations:

- openai/dot-codex/AGENTS.md -> ~/.codex/AGENTS.md
- openai/dot-codex/README.md -> ~/.codex/README.md
- openai/dot-codex/agents/ -> ~/.codex/agents/
- openai/dot-codex/rules/ -> ~/.codex/rules/
- render openai/dot-codex/hooks.json -> ~/.codex/hooks.json by replacing
  both Python executable placeholders with the absolute current Python
  executable using platform-correct command quoting
- openai/dot-codex/hooks/ -> ~/.codex/hooks/
- openai/dot-codex/compatibility.json remains repository metadata; Codex owns
  live ~/.codex/version.json runtime/update state
- openai/dot-agents/README.md -> ~/.agents/README.md
- openai/dot-agents/skills/ -> ~/.agents/skills/

For ordinary files in those directories, if the live file differs, back it up
first, then replace it with the repo baseline.

Record repository-owned tree entries in ~/.codex/agentcore-manifest.json. On
later runs, remove and back up only stale entries named by that manifest. Never
delete unowned skills, plugins, or other user-managed files
merely because they are absent from this repository.

The formerly managed ~/.codex/evals and ~/.codex/templates trees are retired.
When a valid version-1 manifest records files under those exact keys, back up
and remove only those owned files. Preserve unowned siblings, never follow
symlinked parents, and keep unresolved ownership entries for a safe retry. Do
not recursively delete either live directory. If the platform cannot provide
descriptor-relative no-follow unlinking, preserve the files and ownership
entries instead.

Do not copy these paths or patterns:

- .git/
- .codex
- **/.codex
- **/.tmp/
- **/tmp/
- **/cache/
- **/logs/
- **/log/
- **/sessions/
- **/shell_snapshots/
- **/memories/
- **/__pycache__/
- **/*.pyc
- **/*.pyo
- **/*.sqlite
- **/*.sqlite-shm
- **/*.sqlite-wal
- **/auth.json
- **/history.jsonl
- **/models_cache.json
- **/.personality_migration
- virtual environments such as .venv/ or venv/

Config merge contract
---------------------

Handle ~/.codex/config.toml specially.

If no live ~/.codex/config.toml exists, start from the portable baseline and
generate only the target-machine entries listed below: the current agentcore
checkout trust record, ~/.codex/tmp workspace root, and narrow runtime/skill read
grants that resolve on this machine. Do not invent trust or write access for any
other project.

If live ~/.codex/config.toml exists:

1. Back it up before editing.
2. Parse both repo and live TOML if Python tomllib is available.
3. Start from the repo portable baseline.
4. Preserve these live machine-local sections or keys when present:
   - all [projects.*] tables
   - [sandbox_workspace_write].writable_roots
   - [shell_environment_policy].set
   - [hooks.state] and [hooks.state.*] tables
   - [plugins.*] tables
   - any local file_opener setting
   - any target-machine paths that already exist and are intentionally trusted
5. Prefer repo baseline values for general Codex behavior:
   - model
   - review_model
   - model_provider
   - personality
   - reasoning and verbosity settings
   - approval_policy
   - sandbox_mode
   - web_search
   - project_doc_max_bytes
   - project_root_markers
   - agents registry
   - MCP server definitions
   - profiles
   - features
6. Do not preserve stale live paths if the path does not exist on this machine,
   except when the path uses a shell-home convention such as ~/.codex and is
   meant to be created.
7. Do not add host paths from this repository into the live config. The repo
   config should be machine-agnostic.
8. Generate host-specific local entries from the current machine, not from the
   source machine:
   - add ~/.codex/tmp as a writable root when needed for nested Codex runtime
     shims
   - mark only the current agentcore checkout as trusted, because the operator
     explicitly cloned and invoked setup from this repo
   - if the codex binary resolves under the user's home directory, add the
     narrowest practical read grant under [permissions.workspace.filesystem] so
     Codex sandboxes can see their own installed runtime
   - add narrow read grants for installed skill roots that live outside the
     active project, such as ~/.agents/skills, ~/.codex/skills/.system, and
     symlinked custom skill targets with a SKILL.md file
9. Write the merged config atomically when practical.

If a TOML writer library is not available, use a conservative text merge:

1. Copy the repo portable config to a temporary file.
2. Append preserved live machine-local [projects.*], [plugins.*], and clearly
   local path override sections to the end under a comment:
   # Machine-local preserved settings from previous ~/.codex/config.toml
3. Back up the original live config.
4. Replace ~/.codex/config.toml with the temporary merged file.
5. Parse the final file before considering the merge successful.

Permissions
-----------

When practical:

- chmod 700 ~/.codex ~/.agents ~/.codex-agentcore-backups
- chmod 600 ~/.codex/config.toml
- keep ordinary copied text files readable by the user

Validation
----------

After installation or merge, run the strongest local validation available:

1. Parse ~/.codex/config.toml as TOML.
2. Parse the repository openai/dot-codex/compatibility.json contract and copied
   managed JSON files.
3. Run the repository skill integrity check with the target machine's working
   Python executable:
   python3 -m pip install -r requirements-validation.txt
   python3 -B scripts/validate-skills.py
   On Windows, use python.
4. Compile copied hook scripts under ~/.codex/hooks when Python 3 is available.
5. Run a search over managed ~/.codex and ~/.agents paths for accidentally
   copied forbidden runtime files:
   auth.json, history.jsonl, *.sqlite, *.sqlite-shm, *.sqlite-wal, logs,
   sessions, shell_snapshots, __pycache__, *.pyc, .tmp.
6. Run a search for hard-coded paths from the source machine if the clone came
   from a different machine. Search for the source account's home directory and
   any machine-specific checkout roots.
7. Confirm codex is available with:
   codex --version
   if the binary exists.
8. Confirm the sandbox can start when the platform exposes that subcommand:
   codex sandbox linux pwd
   If it fails because the Codex runtime path is not visible, adjust only the
   live machine-local [permissions.workspace.filesystem] read grant. Do not add
   that host path to openai/dot-codex/config.toml.

Do not run codex exec as part of setup unless the operator explicitly asked for
a live backend check. Backend connectivity is environment-dependent and should
not block local file installation.

Final report
------------

Report:

- files and directories installed
- config sections merged from the repo baseline
- machine-local config sections preserved
- files skipped because they are runtime/private/local-only
- backup directory path
- validation commands run and whether they passed
- any remaining unverified assumptions

A successful setup means the live ~/.codex and ~/.agents contain the portable
baseline from this repo, target-machine local config is preserved, forbidden
runtime state was not copied, and validation passed or any skipped validation is
explicitly explained.
